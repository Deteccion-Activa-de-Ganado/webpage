Arquitectura de producción

Tecnología diseñada
para escalar con tu campo

DAG está construido sobre microservicios desacoplados comunicados por mensajería asíncrona. Cada componente escala de forma independiente. Acá explicamos cada pieza y por qué la elegimos.

Diagrama de arquitectura

Cinco microservicios, un sistema

Cada servicio tiene una función clara y se comunica a través de RabbitMQ (asíncrono) o REST (sincrónico).

🧠
Video Processing Service
Python 3.11 · FastAPI · YOLOv8 · ByteTrack · CUDA

El núcleo de IA. Recibe el video por RabbitMQ, ejecuta YOLOv8-seg + ByteTrack, calcula GSD, estima peso, clasifica condición corporal y genera el PDF y video anotado.

YOLOv8-seg ByteTrack FastAPI ReportLab OpenCV
🎬
Video Service
Go 1.22 · Gin · PostgreSQL · S3-compatible storage

Recibe el video por HTTP chunked streaming, lo almacena, y publica en RabbitMQ para disparar el procesamiento. También sirve las descargas del video anotado.

Go/Gin RabbitMQ S3 storage PostgreSQL
📊
Metrics Service
Node.js · TypeScript · Prisma · PostgreSQL

Persiste los resultados del procesamiento IA. Expone la API REST que alimenta el dashboard con datos históricos y actuales de cada vuelo.

TypeScript Prisma ORM PostgreSQL RabbitMQ
👤
User Service
Node.js · TypeScript · Supabase Auth · PostgreSQL

Autenticación y autorización. Supabase Auth para login con JWT. Mantiene establecimientos, lotes y permisos por usuario.

Supabase Auth JWT TypeScript Prisma ORM
🖥️
Desktop UI
Next.js 15 · Electron · TypeScript · shadcn/ui · Tailwind CSS

Interfaz que corre como app de escritorio (Electron) o en el navegador (Next.js). Consume los microservicios y ofrece todo el dashboard al usuario.

Next.js 15 Electron shadcn/ui Tailwind CSS TypeScript

Decisiones de diseño

Por qué elegimos cada pieza

Cada elección tiene una razón. No usamos tecnología de moda sin justificación.

¿Por qué YOLOv8 y no un modelo custom?

YOLOv8 es el estado del arte en detección real-time. La variante -seg agrega máscaras por animal sin sacrificar velocidad. El fine-tuning sobre nuestro dataset de bovinos fue suficiente, sin el costo de entrenar desde cero.

¿Por qué Go para el Video Service?

Subir videos de varios GB requiere streaming eficiente con bajo consumo de memoria. Go es excelente para I/O intensivo con goroutines. Python o Node.js serían subóptimos para este caso.

¿Por qué RabbitMQ y no llamadas directas?

El procesamiento IA tarda minutos. Una llamada HTTP directa daría timeout. RabbitMQ desacopla: el video se encola y se procesa cuando hay recursos, sin bloquear al usuario.

¿Por qué Electron para la app de escritorio?

El dashboard ya estaba en Next.js. Electron empaqueta la misma UI como ejecutable nativo sin reescribirla para tres plataformas. La alternativa hubiera triplicado el trabajo.

¿Por qué z-score para condición corporal?

La condición corporal es relativa al rodeo. 300 kg puede ser normal o bajo según la raza y categoría. El z-score sobre densidad corporal clasifica siempre relativo al promedio del lote, no a un valor absoluto externo.

¿Por qué GSD para estimar peso sin balanza?

El GSD convierte píxeles en metros reales. Con el área de la silueta en m² se aplica una regresión calibrada con bovinos argentinos para estimar peso sin balanza ni contacto con el animal.
